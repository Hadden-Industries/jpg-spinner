# JPG Spinner 2.0 — release-note draft

## Qualification status

**UNRELEASED / NOT QUALIFIED / NOT AUTHORIZED FOR DISTRIBUTION.** This is a
maintained draft, not an announcement or instruction to install a development
package. Application manifest version is `2.0.0.0`; the independently versioned
bundle is `2026.2.0.0`. Neither version number establishes Windows signature
trust, update continuity, certification or release approval.

The [release qualification register](../release-qualification.md) owns the
remaining evidence and accountable roles. Final device/OS, accessibility,
performance, signed-upgrade, source/rights, hosted qualification and Store
rollout gates remain open. Do not substitute local development tests or an
unsigned SBOM-bound package for those outcomes.

## Platforms and prerequisites

Declared targets are Windows 10 build 19045 or later, including maintained
Windows 11 versions, on x86, x64 and ARM64. This is not a claim that every
target OS/device has completed qualification; ARM64 cross-compilation is not
physical ARM64 execution.

Storage transactions require both the executable's `longPathAware` manifest
and the Windows `LongPathsEnabled=1` prerequisite. The app does not change
Windows settings. The qualified recovery backend is deliberately limited to
physical NTFS; FAT32 and other providers without the required established
contract are refused before modification. See
[guarantee limits](../architecture.md#guarantee-limits) for the exact boundary.

## User-visible changes

- Pick a source folder, analyze candidates, review eligibility and preservation
  decisions, then explicitly start processing. Folder access comes from the
  Windows picker, not a path inferred from metadata or a saved display name.
- Corrected copies are the default. They go beneath `JPG Spinner Output` in the
  selected root, inside an exclusively created timestamp/batch directory that
  preserves relative source structure. Existing destinations are not replaced.
- Perfect coefficient transforms are the default. Incomplete edge blocks are
  not silently discarded: trimming requires review of the exact loss and
  explicit acknowledgment.
- Progress, refusal reasons and recovery guidance are presented in the WinUI
  shell. The [native picker/startup repair](../implementation/2026-10-17-native-picker-focus-continuity.md)
  restores diagnostic-export focus continuity and keeps source selection gated
  on completed startup recovery. Its passing development cases are not the
  final accessibility matrix.

## Preservation and recovery

Replacement is opt-in. It requires an independently verified backup beneath
`JPG Spinner Backups` in the selected root and the journal commit gate. Backups
are retained, not automatically deleted; keep a separate independent backup.

Source revisions are rechecked. Unsupported providers, changed inputs and
ambiguous recovery outcomes refuse normal processing. Do not rename, edit or
delete transaction artifacts to try to make recovery succeed. Reconnect the
actual required source grant and follow the displayed recovery guidance.

The [transaction invariants](../architecture.md#transaction-invariants) describe
the verified-backup, immutable-journal and validated-output boundaries. Flush
and replacement operations are not promises of undocumented power-failure
atomicity or physical-media durability.

## Format limits

The policy accepts supported single-image DCT JPEG forms only when the native
codec reports them transformable, including the documented 8-/12-bit coding,
sampling and color-model combinations without color conversion. Predictive
lossless/hierarchical JPEG, unsupported precision, MPO/MPF, C2PA/other JUMBF and
payload-bearing trailing content such as Motion Photos are refused rather than
flattened into a different image.

Exif/XMP orientation and derived dimensions are reconciled. ICC, descriptive,
rights and IPTC metadata follow the explicit
[preservation/removal/refusal contract](../specs/2026-08-30-jpg-spinner-modernization-design.md#8-metadata-reconciliation).
Stale previews are not represented as current images. Extended XMP is preserved
only when no required mutation belongs to the extension; otherwise the app
reports `ExtendedXmpMutationNotSupported`.

Resource boundaries are owned by
[`JpegResourceLimits::production`](../../src/JpgSpinner.Domain/include/jpg_spinner/domain/JpegResourceLimits.h),
not independently redefined by this draft. The codec's intermediate-memory
setting is separate from encoded-file limits and total process memory.

## Privacy

The new application performs local processing without custom network telemetry.
Its bounded local diagnostic records exclude paths, image contents, private
metadata and native exception messages. Export requires an explicit Windows
save-picker grant. See the [privacy contract](../privacy.md) for exact fields,
rotation, retention and export behavior. Final traffic observation and
credentialed-owner revocation of the historical telemetry credential remain
release obligations, not claims supplied by this document.

## Legacy cutover and upgrade

The observed published Store baseline is application `1.1.2.0` inside bundle
`2015.616.2316.3521`; it is not an assumed `1.1.3.0` package. The existing Store
product identity must be preserved. Native construction of a newer unsigned
bundle does not prove a trusted baseline-to-modern upgrade.

The [legacy outcome map](../legacy-cutover-coverage.md) records retained and
deliberately retired behavior. The old Windows Store/C++/CX source and codec
remain quarantined until the accepted pre-cutover gates pass; this draft does
not declare their deletion or the related CodeQL alerts resolved. No shim or
parallel legacy-engine compatibility route is introduced into the new app.

Microsoft-managed signing after certification remains separate from any signed
sideload distribution. Store submission, staged rollout and health observation
are deliberate release-owner actions. Required notices, source delivery and
qualified rights review are tracked in [third-party notices](../../THIRD_PARTY_NOTICES.md)
and the [corresponding-source procedure](../corresponding-source.md). Nothing
here grants distribution clearance or substitutes an unsigned registration for
the signed-upgrade test.
